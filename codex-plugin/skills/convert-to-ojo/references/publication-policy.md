# Publish checked projects to ojo.art

Uploading a project that passes `convert-to-ojo` to `https://ojo.art` is a
supported plugin operation. When the user requests that upload or has explicitly
authorized uploading checked projects to this destination, proceed without a
second confirmation merely because `ojo.art` is production. Reuse that standing
authorization for the selected project; do not upload unrelated local projects.
Analysis-only, conversion-only, no-upload, and proposal-approval limits still
apply. Installing or invoking the skill alone is not permission to upload files.

The authorized upload includes creating the selected new-framework target and publishing its validated artifacts with the next CLI. Requested Team intent is recorded as pending until the next CLI supports it. Reuse scoped upload authorization for these necessary writes. Service and tool denials remain authoritative.

“Passes” means evidence from the actual workspace: compatibility preflight admits
the project, required adaptations are complete, the selected export/runtime is
verified, native type/build/package checks pass, and every required business page
has a compiled entry and a source-backed default snapshot. Apply the validation
contract of the chosen CLI workflow. No unresolved conversion blocker may be
treated as a pass; a framework name, old report or successful CLI help command
is insufficient. Preserve an explicit request to omit snapshots in the report.

Resolve the target from the user's project URL/ID or authorized project creation
in the authenticated account. Missing target information is a clarification,
not a new upload-permission question. Keep production API, login and asset origins
on `ojo.art`; do not reuse staging project receipts. Respect empty-project,
version and retry constraints, and upload only the prepared workspace's required
source/configuration/assets. An upload request does not authorize overwriting an
unrelated project or sending an optimization message.

Use only the verified `@touchine-ai/ojo` 2.x CLI and follow
[project import](../../ojo-workspace/references/project-import.md). Record the
project ID before any retry and distinguish successful upload from hosted canvas
verification. This policy describes user-authorized product upload, not general
production administration; it does not bypass service permissions or tool
approval enforcement. If either rejects the action, report the specific denial.
